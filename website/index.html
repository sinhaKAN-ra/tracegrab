What it does

Built for the way AI agents work — and safe enough to point at a real process.

Call Map

Every method as a box, nested by who called whom, with the data crossing each boundary and the return path back.

Auto-diagnosis

N+1 queries, thrown exceptions, values silently cleared, DB fan-out, heap growth — ranked with evidence and a suggestion.

Agent-native (MCP)

19 tools. One call, auto_debug, runs the whole investigation and returns conclusions.

Safe by default

Secret redaction, least-privilege reads, propose-then-confirm on every live edit, an audit trail, fail-closed mocking.

No JSON needed

Set a breakpoint in the gutter, hit the endpoint from Postman/curl — captured identically, tagged EXT.

Live edits

Change a variable mid-flight to force a branch, then read it back — without touching source.

Get started

A VS Code / Cursor / Windsurf extension. Build, install, debug.

git clone https://github.com/sinhaKAN-ra/tracegrab && cd tracegrab
npm install
npm run build          # webview + host
npm test               # host + call-tree + safety suites
npx vsce package       # → tracegrab-*.vsix
code --install-extension tracegrab-*.vsix
  1. F5 your API so it runs under the debugger.
  2. Run “Tracegrab: Start” and set breakpoints (gutter or panel).
  3. Hit the endpoint — from the panel’s runner, or Postman/curl. Watch the Call Map fill.

Drive it with an AI agent

Register the MCP server once; the agent discovers the tools and the “when to use it”.

{ "mcpServers": { "flow-debugger": {
  "command": "node",
  "args": ["/ABS/PATH/tracegrab/mcp/flow-mcp.mjs"],
  "env": { "FLOW_WORKSPACE": "/ABS/PATH/to/target/repo" }
} } }

Then the agent calls auto_debug({ scenario }) → call map + diagnosis + verdict. Full guide: docs/AGENT_AUTOMATION.md.

Not a generic step-debugger

Those exist and are good. This is a different job: proving AI-changed code still behaves.
