What it does

Built for the way AI agents work — and safe enough to point at a real process.

Call Map

Every method as a box, nested by who called whom, with the data crossing each boundary and the return path back.

Auto-diagnosis

N+1 queries, thrown exceptions, values silently cleared, DB fan-out, heap growth — ranked with evidence and a suggestion.

Agent-native (MCP)

31 MCP tools over stdio. One call — auto_debug — runs the whole investigation and returns a verdict, or drive each step: start a session, set breakpoints, read a pause, mutate a variable, step, continue.

Safe by default

Secret redaction, least-privilege reads, propose-then-confirm on every live edit, an audit trail, fail-closed mocking.

No JSON needed

Set a breakpoint in the gutter, hit the endpoint from Postman/curl — captured identically, tagged EXT.

Live edits

Change a variable mid-flight to force a branch, then read it back — without touching source.

Get started

A VS Code / Cursor / Windsurf extension. Build, install, debug.

git clone https://github.com/sinhaKAN-ra/tracegrab && cd tracegrab
npm install
npm run build          # webview + host
npm test               # host + call-tree + safety suites
npx vsce package       # → tracegrab-*.vsix
code --install-extension tracegrab-*.vsix
  1. F5 your API so it runs under the debugger.
  2. Run “Tracegrab: Start” and set breakpoints (gutter or panel).
  3. Hit the endpoint — from the panel’s runner, or Postman/curl. Watch the Call Map fill.

Built to be driven by AI agents

Tracegrab is MCP-native: it ships a server exposing 31 tools so an AI coding agent (Cursor, Claude, Kiro, any MCP client) can set breakpoints, run a flow, read the live runtime, and decide what changed — without a human in the loop.

{ "mcpServers": { "tracegrab": {
  "command": "node",
  "args": ["/ABS/PATH/tracegrab/mcp/flow-mcp.mjs"],
  "env": { "FLOW_WORKSPACE": "/ABS/PATH/to/target/repo" }
} } }

One-shot investigation

auto_debug({ scenario }) sets the breakpoints, drives the calls, builds the Call Map, runs the detectors, and returns a verdict + ranked findings in a single call.

Live session control

start_debug_session, get_pause_state, debug_step, debug_continue, debug_set_variable — the agent reads a pause, decides, mutates a variable to force a branch, and steps on. Read→decide→act, programmatically.

Headless — no IDE

start_headless_session / collect_trace_headless hold a live debug session with no VS Code open — the same steer loop runs in CI or a pure-agent environment. Node always; Python when debugpy is present.

Prove behaviour changed

save_trace a baseline, compare_traces a later run (REGRESSION / CHANGED / EQUIVALENT), and create_behavior_contract + verify_behavior_contract to gate the change — the same engine the CI runner uses.

Read the runtime

get_call_map, analyze_state, evaluate_expression, get_memory_timeline, get_variable_values, export_mermaid — structured runtime truth the agent can reason over, not a screenshot.

Self-describing & safe

get_capabilities / get_instructions let an agent probe what's possible before committing to a path; get_audit_log records every live edit. Secret redaction and propose-then-confirm are on by default.

The agent reads a bundled AGENTS.md that tells it when to reach for the tool (a ticket, a bug report, "why does endpoint X do Y") and how to turn it into breakpoints + a run. Full guide: docs/AGENT_AUTOMATION.md.

Not a generic step-debugger

Those exist and are good. This is a different job: proving AI-changed code still behaves.
